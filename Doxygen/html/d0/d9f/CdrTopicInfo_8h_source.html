60/// Per-type metadata needed by the middleware layer.
61///
62/// type_name() — ROS2-compatible type name string used when
63/// registering the type with a DomainParticipant.
64/// Follows the "pkg::msg::dds_::TypeName_" pattern.
65///
66/// type_hash() — REP-2011 RIHS01 type hash string, placed in the
67/// DDS endpoint USER_DATA QoS policy (PID_USER_DATA,
68/// 0x002c per OMG DDSI-RTPS v2.5 §9.6.2.2.2).
69/// Format: "RIHS01_<64 lowercase hex>" (71 chars).
70/// Consumed by UserDataFormat.h to build the
71/// REP-2016 KV payload "typehash=RIHS01_<hex>;".
72/// The hash is pinned per message definition and is
73/// stable across ROS 2 distributions. A specialization
74/// may return nullptr when no hash is available for the
75/// type; UserDataFormat.h then emits an empty user_data
76/// payload and callers skip setting the QoS field.
77/// To compute the hash for a new type, use
78/// Util/ros2/compute_type_hash.sh (Docker required).
79/// Full workflow: Docs/ros2/adding_message_types.md.
80///
81/// max_serialized_size() — Initial preallocation hint for the CDR payload size
82/// in bytes, excluding the 4-byte DDS encapsulation
83/// header. Used by FastDDS to pre-allocate payload
84/// buffers. For types with variable-length fields
85/// (strings, vectors) this is a minimum hint, not a
86/// hard limit. The actual size per message instance is
87/// computed dynamically by cdr_serialized_size().
88///
89/// Primary template is intentionally undefined — only specializations are
90/// valid.
91template<typename T> struct CdrTopicInfo;
