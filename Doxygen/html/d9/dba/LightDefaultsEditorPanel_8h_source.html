19// Native (non-Blueprint) editor tool window: scans every light-bearing
20// Blueprint class registered in the currently open level (see
21// ULightDefaultsJsonUtils::ScanLightAssetsInLevel, deduplicated by class),
22// lets an artist edit color/intensity/emissive per class, and saves the
23// result to Config/Lights/Defaults.json. A pure C++ Slate panel instead of an
24// Editor Utility Widget Blueprint -- UE's Python editor API has WidgetTree
25// (a Blueprint's design-time widget tree) marked BlueprintProtected, so this
26// tool cannot be authored headlessly; building it natively in C++ sidesteps
27// that entirely and needs no manual Blueprint wiring.

143// Registers/unregisters a hook on FEditorDelegates::OnMapOpened that
144// reapplies the saved Light Defaults catalog (both UCarlaLight-based and
145// traffic-light) shortly after a map finishes loading. Necessary because a
146// light-bearing actor's own registration-time
147// apply (UCarlaLight::RegisterLight, which runs this same session regardless
148// of this tool) creates its emissive MID too early: confirmed via
149// instrumented testing that a same-tick material change made there gets
150// silently reset by something later in map load (World Partition streaming
151// settling, most likely) before the component's real render proxy is built.
152// Waiting for the concrete "map opened" signal, plus a short extra delay,
153// reapplies once everything has actually settled.
