14/// A path-traced distance sensor ("sensor.camera.rt_lens_distance"): the
15/// geometric twin of sensor.camera.rt_lens.
16///
17/// It renders through exactly the same lens as ASceneCaptureCamera_RayTracedLens
18/// -- same attributes, same Set(), same show_only_* filtering, evaluated per ray
19/// inside the path tracer -- but instead of radiance it outputs, for every
20/// pixel, the EUCLIDEAN distance from the camera origin to the primary hit,
21/// measured along that pixel's (possibly heavily distorted) lens ray. That is
22/// the only depth quantity that is well defined for a fisheye: the view-space Z
23/// a pinhole depth sensor reports collapses to zero at 90 degrees off axis, and
24/// warping a pinhole depth image into the lens can only cover the part of the
25/// frame the pinhole frustum reached (~95% for the NuRec f-theta rigs).
26///
27/// The value comes from a real path-tracer AOV, not from post-processing the
28/// colour image: the ray generation shader records the primary hit distance
29/// into a dedicated R32F render-graph texture next to the existing
30/// albedo/normal/depth AOVs (FPostProcessSettings::PathTracingLensAOV ->
31/// FPathTracingData::LensAOV, see Engine/Shaders/Private/PathTracing/
32/// PathTracingCore.ush), and the capture resolves that texture directly through
33/// the ESceneCaptureSource::SCS_PathTracingLensDistance capture source. Nothing
34/// on that route applies exposure, tone mapping, denoising or quantization, and
35/// the primary ray is fired through the exact pixel centre, so the output is
36/// deterministic metric data rather than an image.
37///
38/// Wire format: one float32 per pixel, in METRES, row major (see
39/// carla::sensor::data::DistanceImage on the client). Pixels whose ray hit
40/// nothing report a very large distance (see PATH_TRACER_LENS_AOV_SKY_DISTANCE).
